# Publishing an Insight

1. Search the Insights titles and the body of related guides before choosing a topic. Identify the buyer, the decision and the existing service that addresses it. Improve an existing guide when it already answers the question.
2. Use an existing article in the same language as the layout reference. Preserve the header, keyboard navigation, reading styles and responsive behaviour. Replace the headline, summary, metadata, social preview and structured data with details specific to the article.
3. Verify factual claims. Link to the issuing authority for permits or platform rules. Obtain approval before naming a client or presenting a result. Describe hypothetical examples as such.
4. Test the next step from the article. Link a reader to a relevant service, guide or published project in the paragraph where it helps a decision.
5. Add the article to its language hub and sitemap. Use a self-canonical clean URL. Add reciprocal localized alternates only when both pages address the same intent. Label links to material in another language.
6. Set publication and modification dates to the actual editorial dates. Omit unknown optional dates. Keep publication dates stable on subsequent edits.
7. Run `python3 scripts/seo_audit.py` from the repository root. Review warnings and resolve errors. Preview the article at phone and desktop widths, follow links, inspect the headline and verify image alternatives.
8. Publish on the cadence that supports verified examples, accurate sources and a useful answer. Skip a scheduled slot when the piece repeats an existing guide.
